# Финансовая аналитика — дизайн (23.11.2026)

## Зачем
Марк хочет видеть динамику работы магазина на Ozon по месяцам: красивые аккуратные диаграммы вместо одного периода на листе «Главная».
Инструмент живёт в разделе «Менеджмент» сайта tea-master-team.ru, но это отдельный проект: свой репозиторий (`Mark2803/TeMarketFinancicalAnalysis`), своя служба на сервере.

## Цели
- 4 столбчатые диаграммы по месяцам с января 2026: **Выручка**, **Продано, шт.**, **Прибыль**, **Комиссия Ozon**.
- Выбор периода (с какого по какой месяц), по умолчанию — с января 2026 по последний закрытый месяц.
- Заполнить прошлые месяцы (январь–октябрь 2026) один раз, дальше каждое 1-е число автоматически добавляется прошлый месяц.

## Не цели
- Не пересчитывать финансы заново на сервере — считает только скрипт таблицы, сайт показывает его цифры.
- Не показывать незакрытый текущий месяц.
- Не менять формулы, кнопки и вид листа «Главная».

## Анти-цели (провал, даже если «работает»)
- Цифры на сайте расходятся с листом «Главная» за тот же месяц.
- Автозапуск портит даты, которые Марк поставил на «Главной», или ломает его ручные кнопки.
- В публичный репозиторий попадают ключи (Ozon API, робот Google, БД).

## Подходы (выбран А)
- **А. Таблица копит месяцы в листе «Помесячно», сайт читает лист роботом Google.** История видна и правится в таблице; если сайт лежал — ничего не теряется. Выбран Марком.
- Б. Таблица раз в месяц отправляет итог на сервер, сервер хранит в своей базе. Отклонён: истории не видно в таблице, нужен секрет в скрипте и повторы при недоступности сервера.
- В. Сервер сам считает по Ozon API. Отклонён: дублирование логики, цифры разойдутся с таблицей.

## Часть 1. Скрипт таблицы «Финансы V3»
- Новый файл в Apps Script `Monthly.gs` (код хранится в этом репозитории в `apps-script/Monthly.gs`). Существующие файлы не меняются.
- Новый лист **«Помесячно»** (создаётся один раз, при первом запуске). Одна строка = один месяц:
  `Месяц (2026-01) | Дата с | Дата по | <все показатели с «Главной» по названию из колонки D> | Обновлено (дата МСК)`.
  Повторный расчёт месяца перезаписывает его строку, а не добавляет новую.
- Показатели читаются с «Главной» по названию в колонке D (не по адресу ячейки) — чтобы не сломаться, если строки сдвинутся.
- Расчёт месяца: запомнить A2/B2 → поставить месяц → выполнить «Обновить все данные» и «Сформировать отчёт» (без всплывающих окон) → прочитать D/E → записать строку → вернуть A2/B2. Блокировка `LockService`, чтобы не пересечься с ручным запуском.
- Меню Ozon дополняется пунктами: «Заполнить помесячно с января 2026» и «Пересчитать прошлый месяц».
- Марк ничего не вписывает вручную: один клик «Заполнить помесячно…» (нужен Google для разрешения доступа) — дальше скрипт сам перебирает январь…последний закрытый месяц, сам меняя A2/B2.
  По одному месяцу за запуск с самопродолжением через временный триггер (ограничение Apps Script — 6 минут на запуск). Уже записанные месяцы пропускаются.
- Тот же клик ставит ежемесячный триггер: 1-е число, ~06:00 МСК, считает прошлый месяц. В конце — исходные A2/B2 возвращаются.

## Часть 2. Сайт
- Адрес `tea-master-team.ru/management/finance/`, вход как у других инструментов (PIN в админке → токен `management_access_tokens`).
- Backend: Node 22 + Express 5, порт 3200, `GET /management/finance/api/months` — читает лист «Помесячно» роботом Google (тот же ключ, что у «Себестоимости»), только чтение.
- Frontend: Vite + React, диаграммы — открытая библиотека Apache ECharts. 4 карточки: итог за выбранный период, изменение к прошлому месяцу, столбцы по месяцам с подсказкой при наведении.
- nginx: отдельные `location ^~ /management/finance/api/` → 3200 и `/management/finance/` → статика (должны стоять раньше общего `/management/`).
- Карточка инструмента добавляется в `MANAGEMENT_TOOLS` (TeaMarketV2, ветка `рефакторинг`).

## Решения на усмотрение исполнителя
- Сетка/цвета диаграмм, точный вид карточек, мобильная вёрстка.
- Кэш ответа backend (например, 5 минут).
